# Экспорт занятия для анализа

На вкладке **«Тренажёр · тюнер»**, в правой панели **«Журнал и заметки» → «Экспорт для анализа»**:

1. Заверши занятие и активное упражнение/практику. Для слуховой тренировки без микрофона нажми «Обновить список занятий».
2. Выбери занятие из списка. После остановки микрофона выбирается только что завершённый журнал. Можно экспортировать и старые занятия.
3. Проверь краткую сводку, микрофон и заметки. Сними галочки, если заметки, сведения об устройстве или предыдущие результаты не нужны в отчёте. Сводка показывает до трёх заметок, по 180 символов; полный текст хранится в исходном журнале.
4. Нажми **«Экспорт занятия в ZIP»** и выбери файл. Папка по умолчанию — `%LOCALAPPDATA%\VocalTrainer\Exports`. Автоматической отправки нет.
5. Передай один ZIP для количественного разбора и подготовки следующего JSON-упражнения.

Аудиозаписи, MIDI и файлы текста песен не включаются. Даже если WAV был записан вручную, в ZIP попадут только числовые измерения и события. Заметки включаются по выбранной настройке; перед передачей учитывай их содержимое.

## Состав и версии

Формат `VocalTrainer.Session`, версия схемы **1.0.0**. Версия приложения и версия отчёта независимы.

| Файл | Данные |
| --- | --- |
| `manifest.json` | Идентификатор сессии, версии, время UTC, единицы, настройки включения данных, размеры и SHA-256 остальных файлов |
| `session.json` | Начало, длительность, статус, настройки, фазы, паузы, планы упражнений, итоговые оценки, события и заметки |
| `pitch.csv` | Время, режим, фаза, попытка, индексы секции/ноты, целевые и исполненные ноты/октавы/частоты, центы, confidence, RMS и признак включения в оценку |
| `attempts.json` | Исходные оценки нот и фраз, повторения/пропуски, результаты слухового теста и MIDI; целевые MIDI-ноты и параметры фрагмента |
| `range.json` | Измерения и субъективные оценки комфорта; при включённой истории — ранее сохранённые проверки |
| `progress.json` | Производные метрики текущей сессии и до 20 предыдущих завершённых сессий |
| `diagnostics.json` | Предупреждения, ошибки, калибровка и выбранные сведения об устройстве |
| `README.txt` | Самодостаточное описание состава, единиц и правил интерпретации для получателя |

JSON — UTF-8; CSV — UTF-8, разделитель запятая, десятичная точка, строки CRLF, экранирование по RFC 4180. Список столбцов записан в манифесте. Пустое поле CSV или `null` в JSON означает отсутствие измерения, а не нулевую частоту/ошибку. Исходные имена полей в полезной нагрузке событий сохраняются: при разборе старых журналов учитывай регистр без различия.

`elapsed_ms` отсчитывается от начала сессии (для отдельного запуска практики — от его первого сохранённого события); `mode_seconds` использует часы соответствующего режима, где они сохранены. Паузы остаются событиями, измерения во время остановленной практики не добавляются. `take` отделяет попытки и MIDI-переходы. `section_index`, `note_index` — с нуля, `lap` в MIDI — с единицы.

Ноты используют scientific pitch: C4 = MIDI 60 = До первой октавы. Отклонение = `1200 * log2(detected_hz / target_hz)`. Надёжность требует положительной частоты и confidence ≥ 0,65. Допуски: обычный тюнер и свободное пение ±25 ¢, MIDI ±40 ¢, диагностика диапазона ±50 ¢; в упражнениях сохраняется фактический допуск попытки/ноты.

## Как интерпретировать оценки

`attempts.json` сохраняет исходные результаты без переоценки, включая `timeToLockSeconds`, `longestStableSeconds` и другие показатели, если они есть в журнале. Это результаты существующего алгоритма `frame-assessment-v1`.

`progress.json` использует отдельный алгоритм `sample-metrics-v1`: покрытие = надёжные / все оцениваемые измерения; точность = попавшие в допуск / надёжные. Медиана и средняя ошибка вычисляются среди надёжных измерений. Если голос не распознан, точность равна `null`, покрытие — 0. Если оцениваемых измерений нет, список метрик пуст. Эти показатели основаны на наблюдениях, а не на длительности: они не заменяют будущий переход к оценке по времени.

Подсказки, отсчёт, паузы, промежутки без целевой ноты и отброшенные по повтору/пропуску попытки не входят в производную оценку; строки остаются в CSV с `eligible_for_assessment=false`. После перехода по MIDI ранее собранная попытка исключается из этой оценки. Обычные неудачные попытки сохраняют свои результаты.

Группы сравнения разделены по режиму, целевой MIDI-ноте, допуску и виду эталона. Свободное пение оценивается относительно ближайшей ноты, а не предполагаемой мелодии. Тишину в свободном пении нельзя приписать конкретной ноте, поэтому она остаётся в CSV и сводке `capturedByMode`, но не в метрике отдельной ноты. `capturedByMode` показывает покрытие всех сохранённых наблюдений, включая неоцениваемые; это не оценка точности. При сопоставлении учитывай также темп, режим подсказок и совместное пение, записанные в событиях.

История содержит только более ранние завершённые микрофонные сессии; проверки диапазона ограничены концом выбранного занятия. Персональные заметки и сведения о микрофонах из предыдущих сессий не копируются. SQLite и адаптивная программа не являются частью этого экспорта.

## Совместимость и неполные данные

Поддерживаются существующие JSONL и старые учебные журналы с форматированными многострочными объектами. Последовательности `sequence_pitch_sample` обогащают основную строку и не удваивают измерения. Новые учебные события связаны с `sessionId`; копии из дневного учебного журнала не смешиваются с микрофонной сессией.

Для практики без микрофона доступен отдельный отчёт запуска приложения. Старые учебные журналы не содержат связи с микрофонной сессией: отчёт отмечает возможное дублирование между отдельными экспортами. В старых занятиях может отсутствовать полный план упражнения/MIDI, RMS или время поиска ноты — эти данные не выдумываются.

Новые журналы отмечают начало/конец прослушивания MIDI и слуховых эталонов: записанные в это время образцы доступны для диагностики, но не повышают точность тюнера. В старых журналах границы такого воспроизведения могли отсутствовать; экспорт предупреждает, что часть образцов тюнера могла записываться во время эталона.

Повреждённые записи пропускаются с предупреждением; после сбоя экспортируется читаемая сохранённая часть. Без `session_end` статус — `interrupted`; при ошибке микрофона новые журналы сохраняют `audio_error`. Слишком большой журнал (>128 МБ) отклоняется с сообщением. Ошибка экспорта сохраняет прежний ZIP, если он уже существует.

`SessionReportArchive.ReadManifest` проверяет состав, отсутствие повторяющихся/небезопасных имён, размеры и SHA-256. Читатель допускает неизвестные поля и версии 1.x, отклоняет неподдерживаемую основную версию. Извлекать архив для проверки не требуется. Первые экспорты имеют схему 1.0.0; старые исходные журналы проверяются отдельно.

Задержка воспроизведения/записи не измерена и не компенсирована; это явно отмечается в диагностике. Числовой отчёт не позволяет судить о тембре, безопасности техники или здоровье голоса.

Выполненные проверки сборки и формата: [EXPORT-VALIDATION.md](EXPORT-VALIDATION.md).
