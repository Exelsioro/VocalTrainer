# Проверка сборки и запуска · 24.10.2026

С 26.10.2026 актуальная сборка находится в `dist/Release`, при необходимости Debug — в `dist/Debug`. Указанные ниже датированные пути относятся к истории проверок и удалены при очистке `dist`. ZIP создаётся только по отдельному запросу в `artifacts/packages`.

Проверка свободного пения и навигации 26.10.2026: пройдены 280 автоматических проверок, включая синтетические измерения голоса, числовой журнал, переходы MIDI с сохранением паузы, оценку после перехода, прокрутку графика, тюнер упражнений и отрисовку семи вкладок без ошибок привязок. Лог — `artifacts/build-release.log`, изображения — `artifacts/navigation-preview`. Физическое воспроизведение и реальное пение в микрофон в этих проверках не участвуют.

Автономный Release Windows x64 опубликован через `build.ps1 -SelfContained`. Готовый `dist/Release/VocalTrainer.exe` отдельно запущен: окно открылось и штатно закрылось с кодом 0 (`artifacts/release-smoke.log`). В `dist` оставлена только последняя папка `Release`; ZIP не создавался.

Среда: Windows x64, .NET SDK 10.0.401, .NET / Windows Desktop Runtime 10.0.12.

## Что исправлено

- 25 ошибок компиляции: отсутствующие `using System.IO`, конфликт локальных имён в `SessionLogger`, обращение к отсутствующему `PausableClock.Elapsed`.
- Предупреждения nullable при создании связанных моделей представления: проверки доступности вынесены в методы, вызываемые после инициализации.
- Сбой настоящего запуска WPF: у `ProgressBar.Value` по умолчанию двусторонняя привязка, несовместимая с `ExerciseProgress` и `Melody.ProgressPercent`. Обе привязки явно используют `OneWay`.
- Ошибка NETSDK1176 в обычной сборке: сжатие единого EXE включается только с `-SelfContained`.
- Слияние соседних повторных MIDI-нот: планировщик теперь объединяет сегменты только в пределах одного исходного нотного события.
- Промежуточное неактивное состояние между MIDI-отсчётом и практикой, а также запуск повтора после `Dispose`.
- Загрузка истории с `null` вместо записи, проверка пустых JSON-полей, нечисловых границ фрагмента и бесконечных измерений.
- Ошибка воспроизведения больше не оставляет ссылку на освобождённый аудиоплеер.

## Проверки

- Алгоритмы: синтетические сигналы детектора, оценка интонации и диапазона, JSON, история, журнал JSONL, MIDI-парсер, смена темпа, фрагменты, повторы и горячие клавиши.
- MIDI-модель: отсчёт, непрерывное состояние занятости, практика, пауза, остановка и освобождение ресурсов; аудио заменено тестовыми обработчиками.
- WPF: настоящее окно приложения, все шесть вкладок, загрузка комплектного упражнения, привязки данных, отрисовка пользовательских контролов и корректное закрытие. Окно теста прозрачно и не появляется на панели задач.
- Публикация win-x64 с внешним Runtime и автономная публикация через `build.ps1 -SelfContained`.
- Готовый автономный `dist/win-x64/VocalTrainer.exe` отдельно запущен: главное окно создано и отвечает, штатное закрытие завершилось с кодом 0. Состав ZIP проверен: EXE, PDB, четыре JSON-упражнения и демонстрационный MIDI.

Основной результат: `dist/win-x64/VocalTrainer.exe`, архив `dist/VocalTrainer-win-x64.zip`. Автономной сборке не требуется отдельно установленный .NET Desktop Runtime. Примеры упражнений и MIDI включены в дистрибутив.

Повторить полную проверку и сборку:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -SelfContained
```

## Границы проверки

Реальный микрофон, физическое воспроизведение и ручная WAV-запись не проверялись. Тесты не включают микрофон и не записывают голос. В проверочной среде использован локальный кеш NuGet; сетевой аудит уязвимостей пакетов отключён только переменной окружения текущего процесса из-за недоступности NuGet. Настройки аудита проекта не менялись.
